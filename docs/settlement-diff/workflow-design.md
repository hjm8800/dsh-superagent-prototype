# 竣工资料与结算逐项对比工作流 · 设计说明

## 一、背景与目标

配网大修/检修项目在结算阶段通常有两套资料：原版（原竣工/原送审）与新版（修订/送审后）。两套资料各自包含：

1. **竣工资料工程量描述**（竣工报告工作簿：主要工程量文字、隐蔽接地记录、安健环、清理旧线路、签证等）；
2. **材料清册**（甲供/乙供未计价材料、配件）；
3. **审核结算**（检修工程总表、专业汇总表、单位工程表）。

人工比对存在三个问题：跨表汇总口径不一致、名称/规格写法不一致导致漏配、只看总额看不出金额影响项。本工作流把三块资料解析成结构化条目，按统一规则匹配并输出“数据对比表 + 文字分析报告”，作为结算复核、审核核减/核增说明、资料完整性检查的底稿。

当前版本为可运行 MVP，已能直接解析某 10kV 线路大修项目的 2025 版/2026 送审版真实资料并产出对比结果。

## 二、工作流步骤

```
原版目录 ─┐                                     ┌─ 数据对比表.xlsx
          ├─ 文件识别 ─ 资料提取 ─ 逐项匹配 ─ 差异/风险 ─ 项目分析 ─┼─ 对比分析报告.md
新版目录 ─┘   (reader)    (items)    (matching)   (diff)     (build)   └─ 对比分析报告.docx / summary.json
```

1. **文件识别**：遍历老/新目录中的 `.xls/.xlsx/.xlsm`，读取工作表名与文件名，按特征判断为“检修结算书”或“竣工报告”，同一类可多文件。
2. **资料提取**（readers）：
   - 结算书：表一金额 → totals；表二甲/表三甲项目划分 → 分部；表三甲 `定额/主材/配件` 行 → items；甲供/乙供未计价材料、配件汇总 → 材料 items 与合计；
   - 竣工报告：任意工作表长文本 → texts；隐蔽接地汇总/安健环/清理旧线路/拉盘/底盘 → tables 与工程量 items；空记录写 warnings。
3. **逐项匹配**：先按业务键聚合，再按精确/名称+单位/相似/疑似改名四级匹配，剩余为新增/删除。
4. **差异与风险**：计算数量差、单价差、金额差与变化率，给出九类状态和高中低风险（规则见 README）。
5. **项目分析**：生成中文结论、资料完整性与口径发现、重点风险清单；结算同时给出表一/下浮后/含配件三种口径。
6. **输出**：数据对比表 Excel（15+ 工作表）＋文字报告 Markdown/docx ＋机读 summary.json。

## 三、数据口径（关键设计）

| 场景 | 口径处理 |
| --- | --- |
| 结算总额 | 原版取表一“设备检修费/施工费”；新版优先“下浮后送审金额”，无则设备检修费；报告另列“含配件完整口径” |
| 配件/甲供配件 | 两版表一常把配件购置费/甲供配件材料费单列且不计入工程总费用合计；工作流单独对比并在发现项中提示口径不一致 |
| 材料清册 | 主对比只看乙供未计价材料（两年口径可比）；甲供清单、配件清单为补充口径，原版缺清单时明确“无法逐项对比”而非误报新增 |
| 表三甲主材 | 作为补充口径单独对比（含甲供主材），并提示名称改写导致的“删除+新增”需按规格归并 |
| 竣工工程量 | 文字描述按“同单元格位置优先、相似度其次”配对；接地工程量按材料汇总；原资料缺表/空记录作为资料完整性问题 |

## 四、匹配与差异规则

- **业务键**：结算定额 = `定额编号+单位`（无编号时名称+规格+单位）；材料/工程量 = `名称+规格+单位`（全半角、空格、Φ/×、括号备注等规范化后）。
- **聚合**：同键多行先合并数量与金额，避免因行数差异误判新增/删除。
- **匹配顺序**：精确 → 名称+单位（规格变化）→ 名称相似 ≥82%（单位兼容）→ 疑似改名 ≥70% → 新增/删除。
- **状态优先级**：数量变化 > 规格变化 > 单位变化 > 单价变化 > 金额变化 > 无变化；同量纲单位（m/km、kg/t 等）先换算再比较。
- **风险**：金额差与变化率双阈值（见 README）；名称相似/疑似改名至少中风险，提示人工确认。
- **文本块**：先按单元格坐标配对（同一附页的新旧版本），再按相似度配对；输出无变化/修改/新增/删除与相似度、字数变化。

## 五、真实项目应用（方法验证，数据不随代码提交）

已用一套真实的配网大修项目资料（原版 = 上一年度资料，新版 = 本年度送审资料；结算书由 4 个工作表增至 14 个工作表、竣工报告由 5 个增至 14 个）在本地只读验证了整条流程，同类真实资料与结果均不进入本仓库。验证要点（不列具体项目与金额）：

- **结算双口径**：按表一口径（设备检修费）新版较原版下降约一成；但把配件购置费计入后，两版“含配件完整口径”基本持平。工作流会同时输出三种口径并在结论中提示口径风险。
- **材料分口径**：乙供未计价材料大幅减少，新版另有甲供材料与配件清单；工作流把“原版缺少甲供清单”识别为资料/口径问题，而不是把甲供材料误报成“新增项”。
- **竣工工程量**：新版竣工报告新增安健环、清理旧线路、隐蔽接地、拉盘底盘等记录；原版接地汇总为空记录。工作流能提取新版接地材料数量，并把原资料缺项写成“资料完整性”发现。
- **文本描述**：新版主要工程量文本有新增与改写，工作流按“同单元格位置优先、相似度其次”配对，输出无变化/修改/新增/删除与字数变化。
- **解析正确性**：表一关键金额与文件合计行一致；表三甲定额/主材/配件行、甲供/乙供材料合计、接地/安健环/拆旧条数与原件一致（详见本地校验记录，不提交）。

## 六、输出物

| 文件 | 内容 |
| --- | --- |
| `<项目>-数据对比表.xlsx` | 总览（关键指标/结论/发现/风险汇总）、审核结算汇总与逐项差异/新增删除/全部明细、材料清册乙供/甲供/配件/主材口径、竣工工程量接地/安健环拆旧/文字描述/全文、风险与建议、说明 |
| `<项目>-对比分析报告.md/.docx` | 一、资料与口径；二、总体结论；三、审核结算差异；四、材料清册差异；五、竣工资料工程量差异；六、重点风险与建议；附说明 |
| `<项目>-summary.json` | 完整 Comparison 结构（项目/文档/差异/汇总/结论/风险），供系统对接与二次分析 |

## 七、MVP 边界与后续

- 已支持：真实结算书（表一/表二甲/表三甲/材料汇总）与竣工报告（文本/隐蔽/安健环/拆旧/拉盘底盘）自动解析；单项目老/新目录对比；Excel/Markdown/Word/JSON 输出；匿名演示与测试。
- 暂不支持：PDF/DOCX/博微 BDY3 等其它来源；多项目批量跑批（可在外层脚本/agent 循环调用）；人工校正界面；登录权限与审批流；与内部《工程资料管理》系统/结算 AI 工作台的系统对接。
- 后续建议：①补一个“项目清单批量跑批 + 结果汇总”入口（一次跑多个项目并输出跨项目差异汇总）；②对经常出现的材料名称/规格差异维护同义词表；③增加人工确认清单（标记“名称相似/疑似改名/单位变化”条目）导出；④与结算 AI 工作台集成，把对比结果作为“三算对比”的补充视图。
