# 博微结算软件自动化可行性评估（授权环境）

## 一、现状

- 9月投产资料的附件5预算原生文件为 `.BDY3`，通常对应**江西博微配电网工程造价软件**（具体产品名/版本需业务确认）。
- 当前执行机器未安装博微，无软件授权、版本号、进程/控件信息和测试项目，无法对真实目标做注入或 UI 探测。
- 本机已有 `tools/win-auto-probe`：只读列出窗口、子控件和截图，但需要目标软件安装后才能对博微运行。

## 二、路线对比

| 路线 | 技术可行性 | 主要风险 | 建议 |
| --- | --- | --- | --- |
| 官方 API/SDK/COM/批量导入导出 | 取决于厂商 | 需厂商支持、可能收费/排期 | 最优先，先问博微 |
| 文件级对接（XLSX/XML/BDY3 导入导出） | 较高 | 格式/版本限制、导入规则不透明 | 二期优先，最稳 |
| UI 自动化（Win32/UIA/RPA） | 中高 | 控件随版本变化、弹窗/模态框 | 先用探针验证 |
| DLL 注入 | 技术可行 | 版本升级易失效；可能违反授权/EULA；触发安全软件；数据损坏；无厂商支持；审计难解释 | 仅授权测试环境、前三种不可行时做 POC；不做绕过授权/反调试/加密 |

结论：**DLL 注入技术上可行，但不适合盲写，也不建议直接上生产**。先做只读探针和 UI 自动化评估；确实覆盖不了，再做注入 POC。

## 三、注入 POC 前置条件（需要业务/IT提供）

1. 博微安装包和有效授权；最好是一台**隔离测试机/虚拟机**，不与生产库、生产账号混用。
2. 软件全称、版本号、32/64 位、使用的 UI 框架（如已知）。
3. 要自动化的操作清单：建项目、导入预算/材料、生成结算书、导出 PDF/Excel、签章前检查等，按优先级排序。
4. 一个测试项目和样例数据（匿名化即可）。
5. 厂商/公司信息安全确认：允许自动化、允许在测试环境做注入 POC；不绕过授权和加密，不碰生产数据。
6. 回滚方案：测试机快照、数据库备份、失败即停止。

## 四、建议步骤

1. 在测试机安装博微，建一个测试项目。
2. 运行 `probe.py --process <进程名>`，记录窗口、控件、菜单、弹窗和导入导出入口。
3. 先试 UI 自动化（Win32/UIA/RPA）完成“打开项目→导入数据→生成结算书→导出”的只读/测试写操作。
4. 如果关键控件不可达，再设计注入 POC：进程/模块识别、注入方式、通信通道、异常处理、操作日志、数据校验、回滚；只注入测试进程。
5. 同一份输入分别手工操作和自动操作，比对生成文件/金额/工程量，确认一致后再讨论生产化。

## 五、边界

- 只做**授权范围内**的自动化；不绕过软件授权、加密、反调试或安全控制。
- 先只读后写入；生产环境默认不启用注入 POC。
- 所有自动操作留日志和输入/输出快照，便于审计和回滚。

## 六、当前可交付

- `tools/win-auto-probe`：只读探针，已在 Notepad 上验证可列窗口/控件/截图。
- 本评估文档：路线、风险、前置条件、测试步骤。
- 待业务提供博微测试环境后，再落注入或 UI 自动化代码。
